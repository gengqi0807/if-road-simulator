# 如果路｜48 小时 Web MVP 执行清单

## 目标与优先级

最终必须让评委在 3 分钟内完成：目标输入 → 3 次分步选择 → 后果分析 → 时间线回溯 → 路径对比 → 条件化攻略。

优先级：

1. **P0 完整可演示**：本地/线上均可运行，LLM 或知乎接口失败时自动使用 Demo JSON。
2. **P1 真实知乎接入**：OAuth 登录、用户信息、知乎搜索/回答摘要或收藏（权限允许时）。
3. **P2 增强项**：真实发布、多周目、第二场景、移动端。

## 三人角色

### 成员 A：全栈与状态机负责人

- [ ] 初始化 Vite/React 或 Next.js 项目，配置环境变量和 lint。
- [ ] 定义 `Session`、`Step`、`Branch`、`Analysis`、`Report` TypeScript 类型。
- [ ] 实现 `POST /api/sessions`：创建会话并返回第一步。
- [ ] 实现 `POST /api/sessions/:id/choose`：保存选择、计算指标、返回分析和下一步。
- [ ] 实现 `POST /api/sessions/:id/backtrack`：按 step 建立新分支，不覆盖旧记录。
- [ ] 实现 `GET /api/sessions/:id/timeline`、`POST /api/compare`、`POST /api/reports`。
- [ ] 将存储抽象为 `DemoStore`/`SupabaseStore`，通过环境变量切换。
- [ ] 增加统一错误格式 `{ ok, data, error, request_id }`。
- [ ] 增加 LLM 超时、知乎 API 失败、数据库失败的降级处理。
- [ ] 完成线上部署、健康检查、构建脚本和最终联调。

验收标准：

- 新会话 1 秒内返回第一步和 4 个选项。
- 选择后能看到分析、指标、引用、时效标签和下一步选项。
- 回溯不会删除旧路径，至少能保留 A/B 两条分支供对比。
- 所有外部服务不可用时，核心 Demo 仍可完整走通。
- `npm run build` 成功，线上地址可从无痕窗口打开。

### 成员 B：前端与 UI 负责人

- [ ] 将现有首页视觉整理为设计 token：主蓝 `#1859D4`、深蓝 `#0C2340`、背景 `#F6F9FE`、成功绿、警示橙。
- [ ] 完成入口/目标页：知乎登录、先体验、目标输入、场景和约束的最小表单。
- [ ] 完成推演页：状态栏、选择卡、AI 分析卡、知乎来源卡、下一步按钮。
- [ ] 完成时间线页：节点、已选路径、回溯按钮和分支标记。
- [ ] 完成对比页：总时间、掌握度、考试收益、遗忘速度、时效风险表格。
- [ ] 完成报告页：全局复盘、条件化攻略、复制按钮、模拟发布按钮。
- [ ] 增加加载、空态、错误、离线 Demo 状态和 Toast 提示。
- [ ] 用固定 Demo 数据先完成页面，不等待后端接口。
- [ ] 适配 1280px 笔记本和 1440px 投影展示；移动端暂不开发。

验收标准：

- 评委无需说明即可理解“当前第几步、资源状态、下一步做什么”。
- 每次只展示当前选项，不提前显示完整决策树。
- 选择反馈在 300ms 内出现；分析加载态不超过 2 秒（超时显示降级提示）。
- 所有按钮有 hover/disabled 状态，文字不溢出，投影环境可读。
- 从首页到报告页不出现控制台报错。

### 成员 C：知乎接入、LLM 与内容负责人

- [ ] 阅读并实现黑客松 OAuth：state 生成、HttpOnly Cookie、回调校验、Token 服务端保存。
- [ ] 接入 `GET https://openapi.zhihu.com/user` 获取授权用户基础信息。
- [ ] 核对赛事分配的 App ID、App Key、redirect_uri；不把密钥提交 Git。
- [ ] 根据权限接入知乎搜索、回答摘要或用户收藏；每次请求增加缓存和去重。
- [ ] 封装 `ZhihuProvider`，接口失败返回统一错误，不阻塞 Demo。
- [ ] 固化 `data/demo/luobida-path.json`，包含至少 3 步、2 条分支、5 条来源和时效字段。
- [ ] 编写 LLM Prompt 和 JSON Schema：分析、指标、卡点、下一步、evidence、freshness。
- [ ] 优先调用知乎提供的 LLM API；若无公开 Chat/JSON Schema 接口，先使用兼容 OpenAI Chat Completions 的适配器。
- [ ] 对 LLM 输出做 JSON 校验；失败时回退预生成分析。
- [ ] 准备 3 分钟演示脚本、断网脚本和评委问答。

验收标准：

- 正确 state 可登录；缺失、篡改、过期、重复 state 均被拒绝。
- 前端永远看不到 App Key、Access Secret、OAuth Token。
- 至少一次真实知乎 API 请求成功，并在 UI 展示来源标题、作者、时间和链接。
- LLM 输出 100% 通过 JSON Schema；失败有可见降级提示。
- 断网时仍能完成完整演示，来源显示为“预置 Demo 资料”。

## API 能力判断与解决方案

知乎黑客松资料明确支持 OAuth 用户基础信息；用户创作、关注、收藏需要同时具备 Access Secret；故事/知识接口无需鉴权但不是通用内容 API。LLM API 的具体 endpoint、模型名、额度和是否支持 JSON Schema 需要以你们拿到的赛事控制台文档为准。

若知乎 LLM API 支持 Chat Completions：直接接入，设置 6 秒超时、结果缓存和 JSON Schema 校验。

若只支持普通文本生成：要求模型输出 JSON，并用 Zod 校验；校验失败使用预置分析。

若没有可调用的 LLM endpoint 或额度不足：演示使用预生成 JSON；真实知乎数据仍可独立接入，LLM 层替换为 OpenAI-compatible provider 或本地规则引擎，不影响产品闭环。
